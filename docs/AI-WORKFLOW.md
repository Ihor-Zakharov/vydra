# AI-воркфлоу: идеальный UI и консоль за одну сессию

Цель сессии — два трека за одно окно лимитов подписки (Max, 5 часов):
- **UI-трек** — идеальный интерфейс, только ПК и только тёмная тема «чёрная дыра» в духе KOCMOC / KOCMOC UNLEASHED;
  функции не меняются. Этапы S0–S5 по очереди, каждый — именованный воркфлоу.
- **CLI-трек** — консольная выдра до идеала для Windows + WSL (Ubuntu) и macOS; PowerShell и нативная Windows не
  трогаются, кириллица не приоритет. Один агент параллельно всей сессии, в своём git worktree.

Главная сессия — **дирижёр** (скилл `ui-sprint`): запускает этапы, проверяет итог, отмечает цели, коммитит локально.
Сама код почти не пишет, её контекст держит картину целиком.

## Запуск (завтра)
`cd ~/projects/video-downloader && claude`, затем два отдельных сообщения: сначала `/effort high`, потом:

```
/ui-sprint Запускаем спринт выдры по docs/AI-WORKFLOW.md. Ты дирижёр: код сам не пишешь, ведёшь этапы.
UI-трек — S0→S5 именованными воркфлоу, CLI-трек — агент vydra-cli параллельно в своём worktree с первой минуты.
Сначала предложи цель для /goal. Модели — только Opus 5.5 (max только у vydra-designer) и Sonnet 5.
Только ПК и только тёмная тема KOCMOC / KOCMOC UNLEASHED; телефон, светлую тему и PowerShell не трогать.
После S1 покажи мне кадр первого экрана и сразу иди дальше; мои замечания передавай в args.notes следующего этапа.
После каждого этапа — 3–5 строк отчёта и локальный коммит. Пушить только после моего «да».
```
`/effort high` — дирижёру хватает; max тратится только в агенте-дизайнере. Хватит и просто `/ui-sprint`:
текст после него лишь повторяет главное из этого файла.
Дирижёр предложит цель для `/goal` — подтверди одним нажатием: он будет вести этапы, пока `tools/sprint.py status`
не скажет `SPRINT: ALL DONE`. Между этапами можно `/clear` и снова `/ui-sprint` — всё состояние в файлах
(`docs/sprint/GOALS.md`, `.claude/state/`), дирижёр продолжит со следующего этапа. «Пауза» — остановиться,
`/goal clear` — снять цель.

## Этапы UI-трека
| Этап | Воркфлоу | Кто | Результат | Цели |
|---|---|---|---|---|
| S0 стенд и контракт | `vydra-s0-rig` | mech ×2 параллельно → mech → qa | `tools/ui_rig.py` (все состояния, 4 окна ПК, report.json, листы-контакты), `FEATURES.md`, `tools/e2e.py` + базовый прогон, CSS разнесён по регионам попиксельно, тема всегда тёмная | G1–G3 |
| S1 направление | `vydra-s1-direction` | designer (max) → qa (полнота) → designer | `docs/design/DIRECTION.md`; 3 варианта первого экрана на живой странице, выбран один | G4 |
| S2 фундамент | `vydra-s2-foundation` | ui → designer ⟲ до 2 кругов | токены, типографика, оболочка, сцена первого экрана | G5 |
| S3 регионы | `vydra-s3-regions` | ui ×4 параллельно → designer (все вместе) ⟲ до 2 кругов | форма, загрузки, хранилище, диалоги во всех состояниях | G6 |
| S4 приёмка | `vydra-s4-accept` | qa → mech ⟲ → designer подпись → ui (если нужно) | вёрстка, доступность, движение, консоль, e2e, чистота, галерея | G7–G13 |
| S5 выпуск | скилл `ship` | дирижёр | слияние CLI-ветки, ворота, локальный коммит, HANDOFF; пуш — после «да» | G14, C1–C4 |

Почему так:
- **Разные агенты на разные части страницы** — регионы (`docs/sprint/REGIONS.md`) со своими CSS-файлами; общие
  файлы правятся только точечно (Edit), фундамент на S3 заморожен — это держат хуки.
- **Контекст не раздувается**: каждый агент стартует с чистого листа и получает только свою задачу; дирижёру
  возвращается короткий JSON по схеме, а не простыня отчёта.
- **Направление до исполнения**: дорогой вкус (Opus max) тратится на решения и приёмку, исполнение — Opus high,
  механика и проверки — Sonnet.
- **Всё проверяется глазами**: стенд даёт детерминированные кадры каждого состояния, агенты обязаны смотреть на них
  (хук `SubagentStop` не отпускает исполнителя с правками без прогона стенда).

## CLI-трек
Дирижёр запускает `vydra-cli` на этапе S0 (`isolation: worktree`). Цели C1–C4 в `GOALS.md`: надёжность в WSL
(никаких вызовов без таймаута — корень бага `vydra ui`), матрица реальных загрузок (скилл `cli-matrix`,
итог — `docs/cli/MATRIX.md`), отшлифованный CLI, ветка готова к слиянию без изменений API интерфейса.
Прогресс агент пишет в `docs/cli/PROGRESS.md` своей ветки — если его прервут, новый продолжит с того же места.
Слияние — на S5.

## Механика
- **Скиллы** (`.agents/skills`, у Claude через симлинк `.claude/skills`): `ui-sprint` — плейбук дирижёра;
  `region-pass` — порядок работы над регионом; `ui-rig` — стенд и кадры; `dev-server` — порты и серверы;
  `cli-matrix` — матрица загрузок; `ship` — выпуск.
- **Хуки** (`.claude/settings.json` → `.claude/hooks/`):
  - `SessionStart` — статус спринта в контекст с первой секунды;
  - `PreToolUse Bash` — без атрибуции в коммитах, без force-push, без пуша до «да» пользователя, без `pkill` и
    `taskkill msedge`, без `git stash/checkout/restore/reset/clean` в общем дереве во время спринта; коммитит только
    дирижёр; пульс CLI-агента;
  - `PreToolUse Edit|Write` — секреты; зоны агентов; на S3 только Edit в общих файлах и заморозка фундамента;
    `GOALS.md` отмечает только дирижёр;
  - `PostToolUse` — синтаксис правленого файла (node, py_compile, CSS, JSON); отметки «правил / прогнал стенд /
    тесты зелёные»;
  - `SubagentStop` — исполнитель UI не уходит без прогона стенда после правок, CLI-агент — без зелёного pytest.
- **Цель** — встроенная `/goal` с проверкой по последней строке `python3 tools/sprint.py status`.
- **Референсы прошлых проектов**: визуальный язык KOCMOC / UNLEASHED и движение — `~/projects/video-workflow/docs/`
  (`gd-visual-references.md` §3–4, `research/kosmos-into-math.md` §1–3, `research/motion-craft.md` §3); урок оттуда же —
  вкусовые решения принимает один арт-директор, механику делают остальные; проверка секретов перед выпуском —
  по образцу `syssoft-labs-ai` (`verify-before-push`); тяжёлые вычисления — только через `renderjob`.

## Бюджет (Max, одно окно 5 часов)
Самое дорогое — `vydra-designer` на max: ~5–7 вызовов за спринт (S1 ×1–2, ревью S2 ×1–2, S3 ×1–2, подпись ×1–2).
Исполнители Opus high: S2 1–3, S3 4–8, S4 0–2; CLI-агент один, но долгий. Остальное — Sonnet.
Если лимит кончается: этап возобновляется с кэша (`resumeFromRunId`), CLI-трек — с `docs/cli/PROGRESS.md`.
Порядок на случай нехватки: S0 → S1 → S2 → S3 (форма и загрузки первыми, `args.regions`) → S4.
