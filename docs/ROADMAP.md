## Этап 2 — всё остальное, по порядку

### 2.1 Стабильность в WSL (агент `vydra-cli`, Opus 5.5 — в CLI-треке этапа 1)
- ~~`vydra ui --port <новый>` висит без вывода~~ — исправлено (`bc4f5c9`): `connect()` к закрытому порту в mirrored-режиме WSL висит, проверка теперь через `bind()`.
- Установленный сервер на 8765 принимает соединение, но не отвечает (event loop блокируется синхронным вызовом?).
- Таймауты на всё, что ходит в `/mnt/c`, `powershell.exe`, `cmd.exe`, `explorer.exe`.
- «Показать в папке» из WSL открывает Проводник Windows с выделенным файлом (`wslpath -w`).
- Команда `vydra stop`; повторный запуск установщика сам перезапускает работающий сервер.

### 2.2 Обновления для друга
- `vydra self-update` и плашка в UI «Есть новая версия → Обновить».
- Номер версии растёт с каждым выпуском, `CHANGELOG.md`, теги в git.
- Исправить README: `uv tool upgrade vydra` не обновляет установку из zip — нужен повторный запуск установщика.
- Service worker: новая версия UI подхватывается без Ctrl+F5.

### 2.3 Надёжность загрузки YouTube / TikTok / Instagram
- Еженедельная проверка и обновление yt-dlp, живые тесты по расписанию в CI.
- Cookies: импорт из браузера в один клик вместо ручного `cookies.txt`.
- Ролики с входом (Instagram), лимиты частоты, запасные стратегии форматов — с понятными вопросами пользователю.

### 2.4 Хранилище
- Смена папки вместе со структурой YouTube / TikTok / Instagram / … и вопрос «перенести уже скачанное?»
  (`Library.move_root`, `POST /api/settings/library {move}`) — довести и покрыть тестами.
- В WSL по умолчанию — «Загрузки» Windows.

### 2.5 Консоль «до ума»

### 2.6 CI и выпуск

- Релизы с тегами и заметками.
