## Сделано
### C1 — надёжность в WSL
- **`vydra stop` / `vydra restart`** (`vydra/servers.py`): сервер находится по файловой блокировке
  `<work>/ui-<порт>.lock` и `.pid` рядом — без сети, мгновенно; stop — SIGTERM → 10 с → SIGKILL; restart — SIGUSR1:
  `vydra ui` мягко останавливает uvicorn и перезапускает себя (exec) в том же окне уже новой версией. Серверы
  старых версий (без `.pid`) находятся по владельцу блокировки (`/proc/*/fd`, на macOS `lsof`), останавливаются
  и поднимаются в фоне (журнал `<work>/ui-<порт>.log`).
- **Повторный `install.sh` перезапускает работающий `vydra ui`** (`vydra restart --quiet`). Проверено с временным
  HOME: новая → новая (в том же окне, pid тот же, `started` новый), старая (main) → новая (в фоне).
- **`vydra ui`**: порт 1–65535 (иначе код 2); системный порт (<1024) — сразу понятная ошибка; второй запуск, пока
  первый поднимается, — «уже запускается — жду…», через 8 с понятная ошибка; баннер 0,9 → 0,2 с, `/api/health`
  1,6 → 0,5 с (кэш «Загрузок» Windows на сутки вместо трёх вызовов PowerShell на команду).
- Сервер отвечает не позже чем через 2 с, даже если хранилище на медленном диске (раскладка доделывается в фоне).
- Таймауты: буфер обмена 8 с, обновление yt-dlp 10 мин, иконка ярлыка и обложка MP3 60 с; кэш `wslpath`.
- **«Показать в папке»**: `vydra open|показать [часть названия] [--play]`, `download --показать`; проверено
  глазами-скриптом: Проводник открывается с выделенным файлом и для `/mnt/c/…` (пробелы, запятая, `&`, скобки),
  и для `\\wsl.localhost\…`; ветки WSL / macOS (`open -R`) / Linux — тестами `tests/test_system.py`.

### C3 — ещё
- Ошибки разбора командной строки — по-русски одной строкой, с допустимыми вариантами и «может быть, …?»;
  справка по-русски («Как вызвать», «Ключи», «по умолчанию»), у синонимов (`d`, `скачать`) — полная справка.
- `-o` создаёт папку и понимает `C:\…` в WSL; интерактивный режим не качает повторно; `info` — число роликов
  плейлиста и подсказка `--весь-плейлист`.
- Ctrl+C: консоль убирает папку задачи и копию исходника сразу; второй Ctrl+C во время копирования в хранилище
  убирает недописанный файл и `.part`; фоновые постеры (ffmpeg-сироты) в консоли не запускаются.
- `vydra ui`: закрыли окно терминала (SIGHUP) — мягкая остановка с сохранением очереди; открытые вкладки (SSE)
  закрываются по сигналу сразу (restart 6,8 → 3,2 с, stop 1,2 с).
- README: раздел о консоли переписан (буфер, кавычки, `--json`, коды выхода, stop/restart, cookies, open).
- **Tab-подсказки не работали и в выпущенной версии**: `add_completion=False` (своя команда `completion`), а классы
  оболочек Typer регистрирует только при `add_completion=True` — оболочка получала «Shell bash not supported».
  Исправлено (`_enable_completion`), тест `test_tab_completion_answers_for_bash_and_zsh`.
- Ревью ветки (code-review, 4 находки — все исправлены с тестами): повтор после куска начинается с чистой папки;
  `.pid` «умею перезапуск» — только пока стоит обработчик SIGUSR1, restart, заставший сервер на остановке, поднимает
  новый; `--json --show` — один итог; буфер Linux без графического сеанса — «недоступен», а не «пуст».
- `vydra stop` шлёт сигнал только процессу, который держит блокировку (переиспользованный PID из `.pid` не трогаем).

### Отрезок куском (приоритет пользователя №2 — обрезка)
- Короткий отрезок (≤ 60 с) ролика длиннее 3 мин качается куском (`download_ranges` yt-dlp), а не весь ролик:
  5 с 4K — 87 → 18 с, 8 с 1080p — 37 → 10 с, 10 с из часовой лекции — 4 с (живой тест). Сверено с резом из целого
  ролика (звук ±20–50 мс, кадры PSNR 31–35 дБ). Сбой куска — откат на весь ролик; повтор задачи — всегда весь
  ролик; `VD_SECTION_MAX=0` выключает. Куски длиннее 60 с не берём: YouTube отдаёт их ~2× реального времени.
