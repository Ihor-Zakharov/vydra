## Сделано
### C1 — надёжность в WSL
- **`vydra stop` / `vydra restart`** (`vydra/servers.py`): сервер находится по файловой блокировке
  `<work>/ui-<порт>.lock` и `.pid` рядом — без сети, мгновенно; stop — SIGTERM → 10 с → SIGKILL; restart — SIGUSR1:
  `vydra ui` мягко останавливает uvicorn и перезапускает себя (exec) в том же окне уже новой версией. Серверы
  старых версий (без `.pid`) находятся по владельцу блокировки (`/proc/*/fd`, на macOS `lsof`), останавливаются
  и поднимаются в фоне (журнал `<work>/ui-<порт>.log`).
- **Повторный `install.sh` перезапускает работающий `vydra ui`** (`vydra restart --quiet`). Проверено с временным
  HOME: новая → новая (в том же окне, pid тот же, `started` новый), старая (main) → новая (в фоне).
- **`vydra ui`**: порт 1–65535 (иначе код 2); системный порт (<1024) — сразу понятная ошибка; второй запуск, пока
  первый поднимается, — «уже запускается — жду…», через 8 с понятная ошибка; баннер 0,9 → 0,2 с, `/api/health`
  1,6 → 0,5 с (кэш «Загрузок» Windows на сутки вместо трёх вызовов PowerShell на команду).
- Сервер отвечает не позже чем через 2 с, даже если хранилище на медленном диске (раскладка доделывается в фоне).
- Таймауты: буфер обмена 8 с, обновление yt-dlp 10 мин, иконка ярлыка и обложка MP3 60 с; кэш `wslpath`.
- **«Показать в папке»**: `vydra open|показать [часть названия] [--play]`, `download --показать`; проверено
  глазами-скриптом: Проводник открывается с выделенным файлом и для `/mnt/c/…` (пробелы, запятая, `&`, скобки),
  и для `\\wsl.localhost\…`; ветки WSL / macOS (`open -R`) / Linux — тестами `tests/test_system.py`.

### Самообновление: `vydra update` (задача пользователя, после C1–C4)
- `vydra update` без ключей обновляет выдру из того же места, откуда её поставил установщик (по умолчанию — GitHub
  main), и yt-dlp. Откуда: `--repo/--из` → `VYDRA_REPO` → `<config>/install.json` (пишет `install.sh` через
  `vydra update --record`) → квитанция uv → GitHub main; записанная локальная копия пропала — GitHub.
- «Было → стало»: версия · коммит · дата. Последний коммит — GitHub API (10 с) или git локальной копии; совпадает —
  не переустанавливаем; не узнать — переустанавливаем и говорим об этом. Ключи: `--только-ytdlp`, `--заново`,
  `--проверить`.
- Установка — `uv tool install --force` (как `install.sh`) с резервной копией окружения (~120 МБ, ~1 с): uv упал
  или новая версия не запускается — прежняя возвращается вместе со ссылками в `~/.local/bin`. Проверено: сам uv при
  ошибке сборки, разрешения и отсутствии сети установку не трогает (`.sprint/uv_fail_test.sh`), резерв страхует
  обрыв посреди установки.
- После установки — уже новой версией: yt-dlp, Tab-подсказки (если были), перезапуск работающего `vydra ui`.
- Проверено на временном HOME (`.sprint/update_test.sh`): установка из локальной копии → ui → коммит 1.0.1 →
  `vydra update` без ключей: «1.0.0 · eff6ad9 → 1.0.1 · b8960ff», `/api/health` отвечает 1.0.1, ui перезапущен
  в том же окне, Tab работает; нет сети и сломанная копия — понятная ошибка, выдра 1.0.1 цела, резерва не осталось.
- Найдено этой проверкой: свои процессы (`python -m vydra` — перезапуск, фоновый ui, воркер загрузок, ярлык)
  подхватывали пакет `vydra` из текущей папки — из клона репозитория поднималась старая версия. Теперь `python -I`.

### Заставка интерактивной консоли и настройки (задача пользователя)
- `vydra` / `выдра` без аргументов в терминале рисует заставку (`vydra/art.py`): чёрная дыра KOCMOC UNLEASHED —
  раскалённо-белое кольцо с Доплером, ореол из тонких концентрических колец, графитовый диск с краем в две ступени,
  полоса-горизонт снизу, редкие звёзды, тонкая радужная кайма по кромке кольца; слева — «VYDRA» тонкими строгими
  линиями с широкой разрядкой. Процедурно (поле расстояний → яркость → полублоки «▀»), высота — четверть окна
  (8–16 строк), ширина по окну (до 180); узко — дыра без названия, меньше 48×16 — без заставки.
  Тёмные пиксели «прозрачны» (фон терминала), поэтому это не чёрный прямоугольник.
- Режимы: truecolor → 256 (серая шкала 232–255, кайма — мягкими пастельными ячейками) → 16 цветов → без цвета
  (NO_COLOR: штриховка « ·░▒▓█», ни одного управляющего кода). TERM=dumb, пайп и `--json` — без заставки.
  Отрисовка 16 мс (120×10), 35 мс (180×16).
- `vydra settings` / `выдра настройки`: заставка, хранилище, cookies, файл настроек; `--art on|off`
  (`--заставка вкл|выкл`) сохраняется в общий `prefs.json` (папку хранилища веб-интерфейса не трогает);
  `VYDRA_NO_ART=1` перекрывает. Подсказка — в справке и при входе в интерактивный режим.
- Кадры: `.sprint/artshots/*.png` (рендер вывода через разбор ANSI, шрифт Cascadia Mono).

### Большое хранилище, ссылка на оригинал, смена папки (задача пользователя)
- Контракт для интерфейса — `docs/cli/API-LIBRARY.md`: `GET /api/library` и `GET /api/fs` постранично
  (`limit/offset`, `sort=added|name|size|duration`, `order`, `q`, `type`, `folder`) — без параметров ответы как
  раньше; `GET /api/library/stats`; `GET /api/settings/library/move`; `move` в `POST /api/settings/library`.
- Замеры на синтетике 50 000 файлов (`.sprint/biglib.py`): индекс 15,2 → 2,4 с; весь список 12–27 с → 0,02–0,35 с;
  страница 3–4 мс, поиск 50 мс; папка 0,8–67 с → 0,13 с (страница 22 мс); память 467 → 296 МБ; `vydra list`
  3–6 → 1,5 с. На /mnt/c (10 000 файлов): изменение в Проводнике сверялось полным обходом 37 с — теперь только
  изменившаяся папка, 0,22 с; такт наблюдателя 7,4 → 3,1 с, пауза подстраивается под медленный диск.
- Причины и исправления: чтение API каждые 3 с обходило весь диск (теперь свежесть держит наблюдатель);
  фоновая обработка ставила файлы в очередь при каждом сканировании (1,35 млн в очереди на 50 000 файлов) и
  переписывала 25-мегабайтный индекс после каждого файла (теперь по разу и пачкой раз в 10 с); обход диска
  держал блокировку, и запросы ждали его; `asdict` и `Path` на каждый файл; ответы собирались заново на каждый
  запрос (теперь кэш на ревизию индекса).
- `source` (ссылка на оригинал) есть у каждого элемента; у найденных сканированием — из тега `comment` файла, в фоне
  (заодно название из тега `title`). Консоль: столбец «Откуда» в `vydra list` (домен, Ctrl+клик открывает),
  `vydra open --source` / `выдра показать --оригинал`; браузер Windows в WSL, `open` на macOS.
- Смена папки: интерфейс слал `move: true`, а сервер его молча игнорировал — перенос не работал. Теперь
  переносит (из текущей папки или из прежней, если новую уже выбрали), с ходом переноса; обрыв посреди копии не
  плодит « (2)». Проверено `.sprint/move_test.py`: 200 файлов ext4 → /mnt/c, kill -9 через 4 с, повтор — всё
  на месте, содержимое совпадает (sha1), id те же, дублей и .part нет, чужое не тронуто; обратно — тоже.
  Консоль: `vydra settings --storage <папка> [--move]`, `--storage-reset` (`--папка`, `--перенести`, `--папка-сброс`).

### Язык консоли: `vydra lang ru|en` (задача пользователя)
- По умолчанию — английский. `vydra lang ru|en` и `выдра язык ру|англ` (ru/ру/рус/русский, en/анг/англ/английский),
  без аргумента — текущий язык и как переключить; выбор — `lang` в `prefs.json`, `VYDRA_LANG` главнее; Tab
  подсказывает `ru`/`en`; язык виден в `vydra settings`.
- Переведено всё, что печатает консоль: справка (панели, подписи Typer, ошибки разбора Click — по-английски
  компактно, без русских синонимов ключей), баннер, интерактивный режим, вопросы, прогресс, итоги, ошибки
  с подсказками, `settings`, `update`, `doctor`, `list`, `folder`, `cookies`, `lang`. В справке верхней строкой —
  «Language: vydra lang ru | en» / «Язык: выдра язык ru | en».
- Устройство: `vydra/i18n.py` (`tr` — строки консоли, ключ — русский текст; `tr_msg` — готовые сообщения других
  модулей: точное совпадение → шаблоны → по частям «a — b», «a; b»), таблица — `vydra/i18n_en.py`. Русские
  синонимы команд и ключей работают на обоих языках, в английской справке скрыты. `--json`: ключи, статусы
  и коды одинаковы, человеческие тексты — на языке консоли.
- Попутно: `python -m vydra` называл себя в справке и ошибках `__main__` (так запускают мост и перезапуск) —
  теперь `vydra`; порядок `--help/-h` в справке больше не прыгает (Click отдавал множество).
- Тесты `tests/test_i18n.py`: у каждой строки консоли есть перевод с теми же подстановками (обход AST), по
  умолчанию en, сохранённый выбор и перекрытие переменной, справка en/ru, ошибки разбора, итог загрузки и ошибки
  с подсказками по-английски, `--json` одинаков на обоих языках. Остальные тесты идут на русском
  (`VYDRA_LANG=ru` в `tests/conftest.py`).
- Кадры справки: `.sprint/artshots/help-en.png`, `.sprint/artshots/help-ru.png`.

### Отрезок куском (приоритет пользователя №2 — обрезка)
- Короткий отрезок (≤ 60 с) ролика длиннее 3 мин качается куском (`download_ranges` yt-dlp), а не весь ролик:
  5 с 4K — 87 → 18 с, 8 с 1080p — 37 → 10 с, 10 с из часовой лекции — 4 с (живой тест). Сверено с резом из целого
  ролика (звук ±20–50 мс, кадры PSNR 31–35 дБ). Сбой куска — откат на весь ролик; повтор задачи — всегда весь
  ролик; `VD_SECTION_MAX=0` выключает. Куски длиннее 60 с не берём: YouTube отдаёт их ~2× реального времени.
