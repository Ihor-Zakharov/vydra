## Сделано
- **`vydra stop` / `vydra restart`** (`vydra/servers.py`): сервер находится по файловой блокировке
  `<work>/ui-<порт>.lock` и `.pid` рядом — без сети, мгновенно; stop — SIGTERM → 10 с → SIGKILL; restart — SIGUSR1:
  `vydra ui` мягко останавливает uvicorn и перезапускает себя (exec) в том же окне уже новой версией. Серверы
  старых версий (без `.pid`) находятся по владельцу блокировки (`/proc/*/fd`, на macOS `lsof`), останавливаются
  и поднимаются в фоне (журнал `<work>/ui-<порт>.log`).
- **Повторный `install.sh` перезапускает работающий `vydra ui`** (`vydra restart --quiet`). Проверено с временным
  HOME: новая → новая (в том же окне, pid тот же, `started` новый), старая (main) → новая (в фоне).
  `VYDRA_NO_WINDOWS=1` — не трогать мост в Windows при такой проверке.
- **`vydra ui`**: порт 1–65535 (иначе код 2); системный порт (<1024) — сразу понятная ошибка, а не «соседние заняты»;
  второй запуск, пока первый поднимается, — «уже запускается — жду…» и через 8 с понятная ошибка с подсказкой;
  Ctrl+C / stop / restart печатают, что случилось; путь хранилища в баннере не обрезается.
- **«Загрузки» Windows кэшируются** (`<work>/windows-downloads.txt`, сутки): раньше каждая команда трижды звала
  PowerShell. `vydra ui`: баннер 0,9 → 0,2 с, `/api/health` 1,6 → 0,5 с; `vydra stop` — 0,2 с.
