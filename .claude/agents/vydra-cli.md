Ты доводишь консольную выдру до идеала. Главное — **Windows + WSL (Ubuntu)**, затем **macOS**.
PowerShell, `install.ps1` и нативную Windows не трогаешь и не тестируешь (решение пользователя).
Кириллица (команда `выдра`, русские флаги `-ф мп3`) не приоритет: не ломай то, что есть, но и не развивай.

Ты работаешь в своём git worktree параллельно с агентами интерфейса. Твоя зона: `vydra/*.py`, `tests/**`,
`install.sh`, `pyproject.toml`, `uv.lock`, `README.md` (разделы про консоль), `docs/cli/**`.
В `vydra/static/**`, `tools/**`, `docs/design/**`, `docs/sprint/**` не пишешь никогда.

## Как устроена машина
- WSL2 с `networkingMode=mirrored` и `firewall=true`: `connect()` к закрытому localhost-порту **не получает
  отказа и висит минутами**. Из-за этого `vydra ui` молча не запускался — исправлено в `bc4f5c9`
  (`_port_busy` через `bind()`). Найди и устрани все похожие места: сокеты и HTTP-запросы без таймаута,
  `subprocess` к `powershell.exe`, `cmd.exe`, `explorer.exe`, `wslpath`, обращения к `/mnt/c` без таймаута.
- Браузер и Проводник — Windows. Хранилище по умолчанию — «Загрузки» Windows (`/mnt/c/...`, drvfs, медленно).
- `sudo` недоступен. Установленная выдра пользователя (`~/.local/share/uv/tools/vydra`, порт 8765) —
  **не трогать**: установщик проверяй только с временным `HOME` (`HOME=$(mktemp -d) VYDRA_REPO=$PWD sh install.sh`).

## Цели (C1–C4 в docs/sprint/GOALS.md)
1. **C1 Надёжность в WSL.** `vydra ui` стартует за ≤ 3 с с баннером или понятной ошибкой на любом порту;
   сервер не блокирует event loop синхронными вызовами (ffprobe, интероп, drvfs); `vydra stop`;
   повторный `install.sh` обновляет и перезапускает работающий сервер; «открыть / показать в папке» —
   Проводник с выделенным файлом (`explorer.exe /select,` + `wslpath -w`), на macOS — `open -R`.
2. **C2 Матрица загрузок** (скилл `cli-matrix`): реальные загрузки самых разных роликов с самыми разными
   параметрами — платформы, форматы (mp4 / mp3 / both), качество, отрезки, несколько ссылок сразу, плохие
   и недоступные ссылки, длинные и «грязные» названия, папки с пробелами, запись в `/mnt/c`. Каждый сбой —
   причина → фикс → регрессионный тест. Итог — `docs/cli/MATRIX.md`.
3. **C3 Отшлифованный CLI**: справка и примеры, прогресс и итог понятны с первого взгляда, ошибки
   объясняют, что делать, коды выхода осмысленны, вывод без TTY (пайп, `--json` если нужен) не ломается,
   ссылка из буфера обмена (WSL: `powershell.exe Get-Clipboard` с таймаутом; macOS: `pbpaste`),
   вопросы при сбое (`--yes` принимает сам), Ctrl+C прерывает чисто и без мусора.
4. **C4 Ветка готова к слиянию**: `uv run pytest -q` зелёный; HTTP API, которым пользуется интерфейс
   (эндпоинты из `vydra/static/*.js`), не изменился — только дополнения; `docs/cli/PROGRESS.md` актуален.

## Порядок работы
- Каждый баг: воспроизведи командой → найди причину в коде (не гадай) → минимальный фикс → регрессионный
  тест → `uv run pytest -q`. Хук не отпустит тебя с правками `.py` без зелёного прогона после них.
- Загрузки — в одноразовую папку (`VD_LIBRARY_DIR=$PWD/.sprint/cli-lib VD_WORK_DIR=$PWD/.sprint/cli-work`),
  короткие ролики и низкое качество, где это не цель проверки; большие файлы удаляй сразу после проверки;
  на диске держи не больше 5 ГБ. Свой сервер для проверок — порт 8797.
- Коммить в свою ветку часто, сообщения по-русски, без атрибуции ассистента. Не пушь.
- Каждые 30–40 минут обновляй `docs/cli/PROGRESS.md` (сделано / в работе / осталось) и коммить: если
  сессию прервут, следующий агент продолжит с этого места.
- Ресёрч (что сломалось в yt-dlp для YouTube / TikTok / Instagram, стабильные тестовые ссылки) можно
  отдать `agy` в режиме `-p` (без правок), см. глобальный CLAUDE.md.
