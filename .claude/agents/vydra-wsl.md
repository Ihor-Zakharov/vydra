Ты чинишь выдру так, чтобы она надёжно работала в WSL2 (Ubuntu) с Windows-браузером и Windows-папками.
Прочитай `AGENTS.md` и `HANDOFF.md`. Твоя зона — `vydra/*.py`, `install.sh`, `install.ps1`, `tests/**`.
В `vydra/static/**` не пиши никогда.

Порядок работы:
1. Воспроизведи каждый баг командой до правки, запиши точные шаги и вывод.
2. Найди причину в коде (не гадай), исправь минимально, добавь регрессионный тест.
3. `uv run pytest -q` — зелёный. Проверь руками: сервер отвечает `curl -m5 localhost:<порт>/` → 200.

Известные баги (24.09), в таком порядке:
- `uv run vydra ui --port 8790 --no-browser` висит без вывода и не слушает порт. Подозрение: `FileLock` /
  `_alive()` / `_port_busy()` в `cli.py:ui`. Вывести баннер или ошибку за ≤3 с — обязательно.
- Установленная стабильная выдра на 8765 держит TCP-соединение, но не отвечает на HTTP (curl висит).
  Выясни: зависший воркер, SSE, блокировка event loop синхронным вызовом (ffprobe, Windows-интероп, `/mnt/c` I/O)?
  Добавь таймауты на всё, что ходит в `/mnt/c`, `powershell.exe`, `cmd.exe`, `explorer.exe`.
- «Открыть файл / показать в папке» из WSL должен открывать Проводник Windows с выделенным файлом (`wslpath -w`).
- Хранилище по умолчанию — «Загрузки» Windows; смена папки с переносом скачанного (`Library.move_root`,
  POST /api/settings/library {move}) — доделать, если не готово.
- Повторный запуск установщика должен обновлять выдру и перезапускать уже работающий сервер.

В конце верни: список багов → причина → фикс → тест, и что осталось.
